עברית · [English](README.en.md)

> **עדכון:** האפליקציה עצמה נמצאת עכשיו בכתובת הראשית, `https://hitzik1-sys.github.io/scanner-proto/` (שלב 1: סריקה ושליחה). האב-טיפוס שמתואר במסמך הזה עבר לכתובת `https://hitzik1-sys.github.io/scanner-proto/prototype/`. הוראות ההגדרה של גוגל (שלבים ב׳–ג׳) עדיין נכונות, ויהיו בשימוש בשלב 2.

אב-טיפוס שבודק את שלושת החלקים המסוכנים לפני הפיתוח המלא:

1. **סריקה:** זיהוי שולי הדף, חיתוך ויישור בדפדפן (OpenCV.js).
2. **זיהוי טקסט בעברית:** דרך גוגל דרייב, בהשוואה ל־Tesseract שרץ בטלפון.
3. **שיתוף:** האם בן משפחה יכול לקרוא את התיקייה שלך דרך האפליקציה, עם הרשאת `drive.file` בלבד.

לשונית 1 עובדת בלי שום הגדרה. לשוניות 2 ו־3 דורשות חיבור לגוגל (שלבים א׳–ג׳ למטה).

## א. העלאה לאתר חינמי (GitHub Pages)

המצלמה וההתחברות לגוגל עובדות רק בכתובת `https`, ולכן מעלים את התיקייה לאתר.

1. היכנס ל־[github.com](https://github.com) (או צור חשבון חינמי).
2. לחץ **New repository**, תן שם (למשל `scanner-proto`), בחר **Public** ולחץ **Create repository**.
3. בדף הריק לחץ **uploading an existing file**, גרור את **כל הקבצים והתיקייה `js`** מתוך תיקיית `prototype`, ולחץ **Commit changes**.
4. **Settings → Pages**: תחת *Branch* בחר `main` ו־`/ (root)`, ולחץ **Save**.
5. אחרי דקה-שתיים האתר זמין בכתובת `https://<שם-המשתמש>.github.io/scanner-proto/`.

## ב. פרויקט בגוגל (חינם)

ב־[console.cloud.google.com](https://console.cloud.google.com):

1. **פרויקט חדש:** בתפריט הפרויקטים למעלה → **New project** → שם: `Scanner` → **Create**.
2. **הפעלת ממשקים:** *APIs & Services → Library*. חפש והפעל (**Enable**) את:
   - **Google Drive API**
   - **Google Picker API**
3. **מסך ההסכמה:** *APIs & Services → OAuth consent screen* (נקרא גם *Google Auth Platform*):
   - **Get started** → שם אפליקציה: `סורק מסמכים`, מייל תמיכה: המייל שלך.
   - Audience: **External**.
   - תחת **Audience → Test users** הוסף את המיילים שלך ושל בני המשפחה שישתתפו בבדיקה.
   - תחת **Data access** הוסף את ההרשאה `.../auth/drive.file`.
4. **מזהה התחברות:** *Clients* (או *Credentials*) → **Create client** → סוג **Web application**.
   - תחת **Authorized JavaScript origins** הוסף:
     - `https://<שם-המשתמש>.github.io` (בלי הנתיב, בלי `/` בסוף)
     - `http://localhost:8080` (לבדיקה מהמחשב, לא חובה)
   - **Create**, והעתק את ה־**Client ID**.
5. **מפתח API לבורר הקבצים:** *Credentials* → **Create credentials → API key**. העתק אותו.
   - מומלץ: **Edit API key** → *API restrictions* → **Google Picker API** בלבד, ותחת *Website restrictions* הוסף `https://<שם-המשתמש>.github.io/*`.
6. **App ID:** בעמוד הבית של הפרויקט (*Dashboard* / *Project settings*) העתק את **Project number** (ספרות בלבד).

## ג. הזנת הפרטים

שתי אפשרויות:

- **הכי נוח למשפחה:** ב־GitHub פתח את `config.js`, לחץ על העיפרון, הדבק את שלושת הערכים ושמור (*Commit changes*). כך כל מי שנכנס לאתר מקבל אותם אוטומטית.
- **רק לטלפון אחד:** באפליקציה, לשונית **הגדרות**, הדבק ולחץ **שמור**.

שלושת הערכים האלה לא סודיים: הם מזהים את האפליקציה, לא נותנים גישה לחשבון.

## ד. מה לבדוק בטלפון

פתח את הכתובת ב־Chrome. מומלץ: תפריט ⋮ ← **הוסף למסך הבית**.

**1. סריקה**

- [ ] סרוק 3–4 מסמכים אמיתיים: דף על שולחן כהה, דף על שולחן בהיר, קבלה קטנה ומקומטת, דף בתאורה חלשה.
- [ ] בכל אחד: צלם בכפתור "צלם" (מצב ידני, ברירת המחדל). המצלמה נשארת פתוחה, אז אפשר לצלם כמה עמודים ברצף. בסוף לחץ **סיום** ועבור על כל העמודים אחד אחרי השני. האם הפינות זוהו נכון? כמה תיקונים ידניים היו צריכים?
- [ ] נסה גם את "מצב אוטומטי": האם המסגרת החיה תופסת את הדף, והאם הצילום האוטומטי עובד? אחרי כל צילום הוא מחכה שתחליף לדף הבא.
- [ ] **בחר תמונות מהגלריה**: סמן כמה תמונות בבת אחת. האם אפשר לבחור כמה, והאם כולן מגיעות לעריכה אחת אחרי השנייה?
- [ ] גרירת פינות: האם הזכוכית המגדלת עוזרת לדייק?
- [ ] נסה את שלושת הפילטרים. איזה נראה הכי טוב?
- [ ] ברשימת העמודים (אחרי העמוד האחרון): לחץ על עמוד כדי לערוך אותו שוב, נסה **מחק עמוד** ו־**+ צלם עוד עמודים**.
- [ ] מסמך של 2–3 עמודים ← **צור PDF** ← **שתף**: האם וואטסאפ ו־Gmail מופיעים בחלון השיתוף, והקובץ מגיע תקין?

**2. זיהוי טקסט** (צריך להתחבר)

- [ ] **המסמך מהסריקה** ← **הרץ זיהוי דרך דרייב**. בדוק כמה מהטקסט זוהה נכון.
- [ ] אותו מסמך עם **Tesseract**, להשוואה. שים לב לזמן ולאיכות.
- [ ] חזור על זה עם מסמך דוגמה ועם מסמך בכתב יד, אם יש.

**3. שיתוף** (צריך שני חשבונות גוגל, שניהם ברשימת Test users)

- [ ] בחשבון שלך: **צור / עדכן תיקיית בדיקה**, הקלד את המייל של בן המשפחה ← **שתף לצפייה**.
- [ ] בחשבון של בן המשפחה (בטלפון שלו, או **החלף חשבון** למעלה): **בחר תיקייה ששותפה איתי**. רשום אילו בדיקות עברו ✓ ואילו נכשלו ✗.
- [ ] אותו דבר עם **בחר את קובץ האינדקס**.
- [ ] אם בורר הקבצים לא נפתח או לא עובד בטלפון: נסה את אותו שלב במחשב, באותו חשבון. ההרשאה ניתנת לחשבון ולא למכשיר, כך שזו יכולה להיות פעולה חד-פעמית מהמחשב.

## ה. החזרת התוצאות

בלשונית **הגדרות** ← **העתק סיכום**, והדבק אותו בשיחה. כל בדיקה שהרצת נרשמת שם אוטומטית, עם זמנים ופרטי המכשיר.

## ו. מה בעצם הגדרנו, ומה הסיכונים

### שלב א׳ (GitHub): מה עשינו

- **repository:** תיקייה מנוהלת בענן של GitHub, שמחזיקה את קבצי האפליקציה ושומרת היסטוריה של כל שינוי.
- **GitHub Pages:** שירות שמגיש את הקבצים האלה כאתר, בכתובת `https://<שם-המשתמש>.github.io/...`.

האתר מכיל **קוד בלבד**: אין בו מסמכים, אין מסד נתונים ואין שרת. כשמישהו נכנס לכתובת, הדפדפן שלו מוריד את הקוד ומריץ אותו על המכשיר שלו.

**האם הקוד פתוח לכולם?** כן. בחרנו **Public**, ולכן כל אחד יכול לקרוא את הקוד ב־GitHub. גם אם ה־repository היה פרטי (דורש חשבון GitHub בתשלום), הקוד של כל אתר נשלח לדפדפן ואפשר לראות אותו שם.

זה לא סיכון כשאין בקוד סודות, ואין:

| ערך ב־`config.js` | מה הוא | למה זה בסדר שהוא גלוי |
|---|---|---|
| Client ID | מזהה האפליקציה מול גוגל | גוגל מאפשרת להשתמש בו רק מהכתובות שאישרת (Authorized JavaScript origins). אתר אחר לא יכול להתחזות לאפליקציה שלך. |
| API key | מפתח לבורר הקבצים של גוגל | לא נותן גישה לשום קובץ או חשבון. אם הגבלת אותו ל־Picker ולכתובת שלך (שלב ב׳5), אי אפשר להשתמש בו במקום אחר. |
| App ID | מספר הפרויקט | מספר מזהה בלבד. |

**האם כל אחד יכול להשתמש באפליקציה?** כל אחד יכול לפתוח את הכתובת ולסרוק, כי זה רץ בטלפון שלו ולא נשמר בשום מקום. כדי להתחבר לגוגל, המשתמש חייב להיות ברשימת **Test users** (שלב ב׳3). וגם מי שמתחבר רואה רק את הדרייב **שלו**, אף פעם לא את שלך.

### שלב ב׳ (Google Cloud): מה עשינו

- **פרויקט:** "מכולה" בגוגל שמייצגת את האפליקציה. הוא חינמי ולא מחובר לאמצעי תשלום.
- **הפעלת Drive API ו־Picker API:** מאפשרת לאפליקציה לדבר עם דרייב ולהציג את בורר הקבצים של גוגל.
- **מסך ההסכמה:** מה שמשתמש רואה כשהוא מתחבר: שם האפליקציה ואילו הרשאות היא מבקשת. במצב **Testing** רק מי שברשימת Test users יכול להתחבר, עד 100 אנשים.
- **Client ID ו־API key:** הזהות של האפליקציה מול גוגל (ראה הטבלה למעלה).

### למה בכלל צריך פרויקט בגוגל?

הפרויקט נדרש **רק לפיצ'רים שניגשים לחשבון הגוגל של המשתמש**. כל השאר רץ בטלפון עצמו.

| פיצ'ר | צריך פרויקט בגוגל? |
|---|---|
| צילום, זיהוי פינות, חיתוך, יישור, פילטרים | לא. OpenCV רץ בטלפון |
| יצירת PDF | לא |
| שיתוף לוואטסאפ ולמייל דרך חלון השיתוף | לא. זה של מערכת ההפעלה |
| זיהוי טקסט עם Tesseract | לא. רץ בטלפון |
| **התחברות עם גוגל** | **כן** |
| **שמירה אוטומטית בדרייב** (שם קבוע, תיקייה, תגיות) | **כן** |
| **זיהוי טקסט דרך דרייב** (איכותי יותר בעברית) | **כן** |
| **שיתוף בין בני משפחה ובורר הקבצים** | **כן** |

**למה גוגל דורשת את זה:** כשאפליקציה מבקשת גישה לחשבון של מישהו, גוגל צריכה לדעת מי מבקש. הפרויקט הוא מעין "תעודת זהות" לאפליקציה:

- **מסך ההסכמה:** מציג למשתמש את שם האפליקציה ואת ההרשאות שהיא מבקשת.
- **כתובות מאושרות:** רק האתר שלך יכול להשתמש בזהות הזו.
- **ביטול ומגבלות:** המשתמש יכול לבטל את הגישה בכל רגע, וגוגל מגבילה כמה פניות האפליקציה שולחת.

**ומה אם מוותרים על הפרויקט?** אפשר עדיין לשמור בדרייב ידנית: בחלון השיתוף של אנדרואיד בוחרים **"Drive"**, ודרייב שואל לאיזו תיקייה לשמור. אבל מאבדים:

- **שם קבוע:** השם בפורמט `20261017_טקסט` לא ייקבע אוטומטית.
- **תגיות ואינדקס:** אין, ולכן אין חיפוש מסודר.
- **חיפוש לפי תוכן:** אפשרי רק בטלפון עם Tesseract, ורק על מסמכים שנסרקו באותו טלפון. הוא נמחק אם מנקים את נתוני הדפדפן.
- **שיתוף חיפוש בין בני משפחה וגיבוי:** אין.

**בשורה התחתונה:** בלי פרויקט מקבלים סורק פשוט. עם פרויקט מקבלים מערכת לניהול מסמכים. הפרויקט חינמי.

### רשימת Test users: מי יכול להתחבר

האפליקציה מוגדרת בגוגל במצב **Testing**. במצב הזה **רק** המיילים שברשימת Test users יכולים להתחבר, עד 100 אנשים. זו "רשימת מוזמנים".

| | מי שברשימה | מי שלא ברשימה |
|---|---|---|
| פתיחת האתר, סריקה, PDF, שיתוף לוואטסאפ ולמייל, Tesseract | עובד | עובד (לא דורש גוגל) |
| "התחבר עם גוגל" | עובד, אחרי אזהרה *"Google hasn't verified this app"* בכניסה הראשונה ← **Continue** | **חסום.** גוגל מציגה *"Access blocked"* (Error 403: access_denied) |
| שמירה בדרייב, זיהוי דרך דרייב, שיתוף | עובד, רק עם הדרייב **שלו** | לא זמין |

- **אישור חוזר:** במצב Testing גוגל מגבילה את תוקף האישור (בדרך כלל לשבוע), אז מדי פעם יופיע שוב מסך האישור. זו לחיצה אחת.
- **ניהול הרשימה:** Google Cloud Console ← **Audience** (או *OAuth consent screen*) ← **Test users**.
- **הוספה והסרה:** משתמש שנוסף יכול להתחבר מיד. משתמש שהוסר לא יוכל להתחבר מחדש, וגישה קיימת שלו תפוג תוך שעה לכל היותר.

**החלופה: פרסום (Publish app).** ההרשאה `drive.file` לא נחשבת רגישה, ולכן אין צורך בתהליך אימות של גוגל. אחרי פרסום כל בעל חשבון גוגל יוכל להתחבר, וגם אז כל אחד רואה רק את הקבצים של עצמו.

**ההמלצה לשימוש משפחתי:** להישאר במצב Testing. זו שכבת הגנה נוספת וחינמית: רק אנשים שבחרת יכולים להתחבר. החיסרון: האזהרה בכניסה הראשונה ומסך האישור שחוזר מדי פעם.

### מה ההרשאה `drive.file` מאפשרת

כשמשתמש מתחבר ומאשר, האפליקציה מקבלת גישה **רק** ל:

- קבצים ותיקיות **שהאפליקציה עצמה יצרה** (למשל `מסמכים סרוקים (בדיקה)` וה־PDF שבה).
- קבצים שהמשתמש **בחר בעצמו** בבורר הקבצים של גוגל.

האפליקציה **לא יכולה** לראות, לקרוא, לשנות או למחוק שום קובץ אחר בדרייב: לא תמונות, לא מסמכים אחרים, לא Gmail ולא אנשי קשר. גוגל אוכפת את זה בצד שלה, לא הקוד שלנו.

**איפה נשמר אישור הגישה?** בזיכרון של הדפדפן בלבד, לשעה, ואז מתחדש. הוא לא נשלח לשום שרת חוץ מגוגל עצמה, כי אין לנו שרת.

**ביטול גישה בכל רגע:** ב־[myaccount.google.com/permissions](https://myaccount.google.com/permissions) בוחרים את האפליקציה ולוחצים **Remove access**.

### האם הקבצים בדרייב פתוחים לכולם?

**לא.** כל קובץ שהאפליקציה יוצרת הוא **פרטי** כברירת מחדל, כמו כל קובץ אחר בדרייב שלך. רק אתה רואה אותו.

הוא נפתח לאחרים רק אם **אתה** לוחץ "שתף לצפייה" ומקליד מייל. גם אז:

- רק המייל הזה מקבל גישה, ורק לצפייה (לא עריכה ולא מחיקה).
- זה לא קישור ציבורי: מי שמקבל את הקישור בלי שהמייל שלו אושר לא יראה כלום.
- "בטל שיתוף" סוגר את הגישה מיד. אפשר לראות ולשנות את השיתוף גם ישירות בדרייב.

## הערות

- בכניסה הראשונה גוגל תציג "Google hasn't verified this app". זה תקין לאפליקציה במצב בדיקה: **Continue**.
- הבדיקות יוצרות בדרייב תיקייה בשם `מסמכים סרוקים (בדיקה)`. אפשר למחוק אותה בסוף.
- גוגל ממירה עם OCR רק את 10 העמודים הראשונים של PDF, ועד 2MB לקובץ. אם זה מגביל, נמצא פתרון בפיתוח המלא.
- הרצה מקומית במחשב, לבדיקה מהירה: `python -m http.server 8080` מתוך התיקייה, ואז `http://localhost:8080`.
